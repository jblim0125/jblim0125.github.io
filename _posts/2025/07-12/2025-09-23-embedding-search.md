## 임베딩 검색이란?

임베딩 검색은 텍스트를 고차원 벡터 공간으로 매핑해 의미적으로 가까운 문서를 찾는 방식이다.
같은 의미를 공유하는 문장은 유클리드 공간에서 서로 가까이 위치하므로, 벡터 간 거리를 비교하는 것만으로 기존 키워드 검색보다 높은 정확도를 얻게 된다.

## 파이프라인 단계

1. **데이터 준비**: 문서 원문과 메타데이터를 정제하고, 필요하다면 언어 파악·불용어 제거 등 전처리를 수행한다.
2. **임베딩 생성**: Sentence Transformer, OpenAI Embedding API 등 사전학습 모델이 텍스트를 벡터로 변환한다.
3. **벡터 인덱싱**: 생성된 벡터를 FAISS, Milvus, PostgreSQL(pgvector) 등의 벡터 DB에 저장하고 근사 최근접 탐색(ANN)이 가능하도록 인덱스를 만든다.
4. **질의 임베딩**: 사용자의 입력(쿼리)도 동일한 모델로 임베딩해 비교 가능한 벡터를 얻는다.
5. **후처리**: 상위 후보군을 대상으로 rerank, 요약, 하이라이팅 등 추가 로직을 적용해 최종 결과를 결정한다.

## 텍스트 길이에 따른 전략

### 짧은 텍스트(문장, 태그, 로그 메시지)

- 문맥이 충분히 드러나지 않을 수 있으므로 카테고리, 엔티티 등 보조 피처를 함께 임베딩하거나 가중치를 준다.
- 유사한 표현을 묶어 데이터 확장을 해두면 임베딩 모델이 학습하지 못한 표현도 자연스럽게 검색된다.
- 여러 짧은 텍스트를 하나의 토픽 묶음으로 평균·가중 평균하여 하나의 대표 벡터로 관리할 수 있다.

### 긴 텍스트(리포트, 매뉴얼, 연구자료)

- 대부분의 임베딩 모델은 입력 토큰 길이가 제한되어 있으므로 의미 단위로 분할(chunking)해야 한다.
- Chunk 길이를 300~500 토큰 수준으로 유지하고 10~20% 정도 겹치게 하면 문맥이 끊기지 않는다.
- Chunk마다 메타데이터(문서 ID, 섹션 타이틀, 페이지 정보)를 저장해 검색 결과를 다시 원문과 연결할 수 있게 한다.

## 사용자 입력 처리 흐름

1. 사용자의 쿼리를 전처리(언어 감지, 정규화, 약어 확장)해 노이즈를 줄인다.
2. 동일한 임베딩 모델로 벡터를 생성한다.
3. 벡터 DB에서 최근접 이웃을 `top-k`로 검색한다.
4. 결과를 정렬·필터링하고 필요하다면 추가 후처리를 진행한다.

```python
from my_embedding import embed
from my_vector_store import ann_search

def embedding_search(user_query: str, top_k: int = 10):
    query_vec = embed(user_query)
    candidates = ann_search(query_vec, top_k=top_k)
    return rerank(user_query, candidates)
```

## Rerank으로 정밀도 높이기

벡터 검색은 빠르게 후보군을 모으는 데 특화되어 있지만, 항상 1순위가 완벽하지 않을 수 있다.
Rerank 모델은 상위 후보를 다시 읽어 문맥 기반으로 점수를 매겨 순서를 재조정한다.

- **Cross-Encoder 기반**: 쿼리와 문서를 함께 입력받아 관계를 직접 판단한다. 계산량이 크지만 정밀도가 높다.
- **LLM 기반**: 상위 후보를 합쳐 요약하거나 답변 생성에 직접 활용하면서, 최종적으로 사용할 문서를 결정한다.
- **하이브리드**: BM25 등 전통 검색과 임베딩 검색을 합쳐 랭킹 신뢰도를 높인 뒤 rerank를 적용해 두 방식의 장점을 결합한다.

## 구현 팁

- 임베딩과 애플리케이션 언어를 가능하면 일치시키고, 여러 언어가 섞인다면 multilingual 모델을 사용한다.
- 주기적으로 임베딩을 재생성해 모델 업데이트나 도메인 변화에 대응한다.
- 벡터 간 거리는 코사인 유사도, 내적 등 모델 학습 방식에 맞는 지표를 선택해야 한다.
- 검색 품질 평가를 위해 쿼리-문서 정답 쌍을 수집하고 정기적으로 리콜·정밀도를 측정한다.
