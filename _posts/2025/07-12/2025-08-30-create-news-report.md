## 목표

이전 보도자료·자료들을 잘 갈무리해 두고, 질문하면 곧바로 보도자료 초안을 뽑아주는 RAG 시스템
어떤 데이터를 어떻게 뽑아 저장하고 활용해야 하는지 현실적인 설계 가이드를 드릴게요.
바로 도입 가능한 최소구성(MVP)부터, 점진적 고도화 로드맵까지 담았습니다.


1. 목표 정리 (무엇을 잘하게 만들 것인가)
    - 빠른 초안 생성: 사용자가 “신제품 A 출시 보도자료 초안 줘”라고 하면 1차 초안을 30~60초 내 산출.
    - 사실 정확성: 기존 보도자료·사내 문서·승인된 숫자만 근거로 작성(근거 문구/문단을 출처 연결).
    - 톤·형식 일관성: 우리 조직 스타일 가이드(말투, 문장 길이, 표기법) 자동 적용.
    - 재사용성: 과거의 좋은 문장/표현/인용/보일러플레이트를 쉽게 끌어다 씀.
    - 에디터 친화: 초안 → 편집 → 재생성 루프가 빠르고 깔끔.

2. 데이터 소스와 범위 정의 (무엇을 축적할까)
    - 내부 1순위
        - 과거 보도자료 원문(국/영문), 보일러플레이트(회사 소개), 미디어 연락처 블록
        - 발표자료(데크), 제품 백서·FAQ, 브리핑 Q&A, IR 자료(숫자/지표의 출처)
        - 승인된 핵심 메시지(키메시지), 어휘 가이드/금칙어 리스트
        - 제품·서비스 설명서(버전 히스토리 포함), 타임라인/로드맵
        - 로고·제품 사진·인포그래픽 등 미디어 에셋과 사용 가이드

    - 외부(옵션)
	    - 주요 매체 보도(우호/중립/오보 정리), 공공 통계, 업계 용어집

3. 표준 스키마 설계 (정말 중요)
    문서마다 일관된 스키마로 구조·사실·문체 정보를 분리 저장하세요. 아래는 권장 예시.
    1. PressReleaseDoc (문서 단위)
        - id, title, subtitle, slug
        - date(배포일), embargo_until(엠바고), lang(ko/en)
        - sections: [lead(리드문), body(본문), quotes(인용), cta, boilerplate, media_contact]
        - topics(키워드), products(연관 제품), audience(기술/비기술)
        - style_profile(톤: 중립/격식/테크니컬 등), rating(성과·완성도 태깅)
        - sources(근거 링크), assets(이미지·pdf), legal(법무 코멘트)

    2. Event/Announcement (사건·발표 단위)
        - who(회사/부서/파트너), what(출시/업데이트/행사), when, where, why(의의), impact(KPI/수치)
        - version(제품 버전), markets(국가/산업)
        - claims(검증된 주장 리스트: “최초”, “세계 최대” → 근거 필수)

    3. Quote (인용 단위)
        - speaker(이름/직함), quote_text, context(무엇에 관한 발언인가), constraints(변형 허용 여부)

    4. Fact/KPI (사실·숫자 단위)
        - fact_id, statement, value, unit, timeframe, source, approval_state
        - 예: { “DAU”: 42만, 2025Q2, 출처: IR 2025Q2 }

    5. Style/Policy (문체·규정)
        - 숫자·단위 표기(예: 억/만, % 앞뒤 공백), 날짜(“2025년 8월 14일”), 따옴표(“ ”), 회사명 표기 규칙(㈜ 여부), 금칙어

    핵심: 문서의 본문 텍스트와 *검증된 사실(숫자/주장)*을 분리 저장해두면, 생성 시 사실성 검증과 출처 표기가 쉬워집니다.

4. 전처리 파이프라인 (정확한 구조화가 절반)
	1.	수집/정리: 포맷 혼재(PDF, PPTX, DOCX, 이메일) → 텍스트 추출(OCR 포함) → 문서 메타데이터 표준화.
	2.	클리닝: 헤더/푸터, 페이지 번호, 목차 제거. 인용부호·하이픈 통일, 공백/개행 정리.
	3.	구조 파싱
        - 제목/부제/리드문/본문/인용/보일러플레이트/연락처 섹션 검출(규칙+ML 혼합).
        - 연락처(이름·직함·이메일·전화), 엠바고 라인 자동 추출(정규식).
	4.	언어 처치(한국어): 문장 분리(끝마침 표지, 따옴표 내부 문장 보존), 형태소/품사 태깅(용언/체언), 고유명사 추출.
	5.	중복/버전 관리: 거의 동일한 문서 해시 유사도 체크, 최신 승인본만 노출.

5. 지식 추출 (RAG용 “찾아 쓸 수 있는 지식”으로)
    - NER/링크화: 회사/제품/기능/조직/인물/날짜/장소. 동형어(예: 제품 코드 vs 일반명사) 구분.
    - Event 추출: 5W1H(누가/무엇을/언제/어디서/왜/어떻게) + 영향(시장, 고객, KPI).
    - Claim-증거 트리플: (주장, 근거문장/문서, 신뢰도)
        예) (“업계 최초 3nm 적용”, 근거: 특허/전시자료, 신뢰도: 검증완료)
    - Quote 매핑: 인용문 → 화자/직함/맥락(출시/고객성공 등) 연결, 재사용 허용 여부.
    - 키프레이즈/템플릿 패턴: “~는 ~을 통해 ~을 가능케 했다” 같은 문장 골격을 태깅.
    - KPI/수치 파싱: 숫자/단위/기간/비교값(전년 대비 +23%) 안전 추출.
    - 톤/독자 난이도 태깅: 기술/비기술 독자를 위한 가독성 점수.

    가벼운 규칙+모델 조합으로 시작하고, 에디터 피드백을 반영해 추출기를 주기적으로 교정하세요.

6. 저장 전략 (하이브리드가 정답)
	1.	문서 저장소(원문/메타): 객체 스토리지 + RDB(문서 메타, 승인 상태, 버전).
	2.	벡터 스토어(임베딩):
        - 다중 그레뉼러리티: 문단(chunk), 섹션(lead/quote 등), 엔티티/이벤트 단위 각각 임베딩.
        - 하이브리드 검색: BM25(정확한 키워드) + 벡터(의미) + 시간/승인 필터.
	3.	정형 팩트 DB(진실의 단일원천): KPI/Claim/Quote 테이블 → 출처/승인/시점 필수.
	4.	지식 그래프(옵션 고도화): 엔티티↔이벤트↔팩트 관계 맵. “제품X 관련 모든 주장과 출처” 즉시 조회.
	5.	템플릿·스타일 저장소: 문체 가이드, 금칙어, 보일러플레이트 버전 관리.

7. 임베딩·청킹 팁 (실성능 좌우)
    - 청킹 기준: 의미 단위(문단/섹션) + 400~800자 권장(한국어 기준), 섹션 경계는 분리 유지.
    - 섹션 태그 포함: [SECTION=QUOTE][SPEAKER=홍길동] “….” 같은 리치 메타를 청킹 시 프롬프트에 함께 제공.
    - 다중 임베딩: 일반 임베딩 + 키프레이즈 임베딩 + 명사구 중심 임베딩 → multi-vector 검색 성능↑.
    - 한/영 대응: 번역 임베딩(영문 질의에도 한글 문서 매칭), 고유명사 보호.

8. 검색 전략 (Retriever 설계)
    - 쿼리 해석: 질의가 “초안 생성”인지 “팩트 확인”인지 의도 분류 → 다른 검색 파이프라인 적용.
    - 리트리버 앙상블
    - BM25(정확 단어), Dense(의미), Phrase(정확구절), Time-aware(최근/버전).
    - 재순위(rerank): cross-encoder/LLM 재순위로 상위 20→5개 정밀 선별.
    - 제외 필터: 승인 전/엠바고 문서 제외, 프로젝트 코드명→공개명 자동 변환.

9. 생성기(Generator) 설계 (초안 뽑는 법)

    프롬프트 레시피(요약)
    - 입력: 사용자 요청 + 상위 K개 컨텍스트(문단/팩트/인용) + 스타일 가이드 + 스키마(JSON Schema)
    - 지시:
        1.	사실은 컨텍스트 내에서만 사용(새 주장 금지).
        2.	각 핵심 문단 뒤에 **[출처: 문서명#문단ID]**를 은밀히 태깅(내부용/편집용).
        3.	한국어 보도자료 형식 준수(제목/부제/리드/본문/인용/CTA/보일러플레이트).
        4.	금칙어·법무 주의어 자동 교정.
        5.	JSON 구조로 1차 출력 → 렌더러가 문서로 변환.

    출력 스키마 예시(JSON)

    ```json
    {
    "title": "신제품 A 출시…",
    "subtitle": "AI 기반 ○○로 업무 생산성 향상",
    "lead": "㈜모비젠은 2025년 8월 14일…",
    "body": [
        {"type": "para", "text": "핵심 가치 제안…"},
        {"type": "list", "items": ["특장점1", "특장점2"]}
    ],
    "quotes": [
        {"speaker": "홍길동 대표", "text": "고객에게 가치를…", "source_ref": "doc123#q1"}
    ],
    "cta": "자세한 내용은 웹사이트 참조…",
    "boilerplate": "모비젠 소개…",
    "media_contact": {"name":"홍길동","email":"pr@...","phone":"+82-2-..."}
    }
    ```

    톤/형식 세부 규칙(한국어)
        - 날짜: 2025년 8월 14일 / 전화: 02-1234-5678
        - 따옴표: “ ”, 단락은 3~4문장
        - 과장/비교 표현은 근거 필수(예: “업계 최초”, “세계 최대”)
        - 보일러플레이트/연락처는 승인본에서 자동 주입

10. 사실성·안전 장치 (Hallucination 방지)
    - 출처 의무화: 생성된 각 주장 → 팩트 DB/문단 출처가 없으면 붉은 경고(편집기 UI).
    - 엠바고/보안: 엠바고 전 공개 금지 토막문 제거, 내부 코드명 자동 치환.
    - PII/규정: 개인정보 노출 감지, 법무 금칙어 룰 체크, 경쟁사/규제 민감 문구 감점.
    - 숫자 검증: KPI는 팩트 DB 값만 참조(수기 입력 금지). 단위·반올림 정책 자동 적용.
    - 차등 권한: 승인 레벨별로 검색/생성 범위 제한(예: 미승인 인용은 관리자만 조회).

11. 평가·지표 (운영에 필수)
    - Retrieval: Precision@k, nDCG, MRR (정답 문서가 상위에?)
    - 생성품질:
    - 편집시간(TTE: Time-to-edit), 사실 오류 건수, 문체 일치도(스타일 규칙 위반 수)
    - 에디터 만족도(5점 리커트), 재사용 비율(기존 인용/문장 활용률)
    - A/B: 템플릿/리트리버/프롬프트 비교 실험(릴리즈 노트와 함께 기록)

12. 운영·거버넌스
	- 승인 워크플로: 초안 → PR팀 리뷰 → 법무 승인 → 배포본 고정 → “진실의 단일원천” 갱신.
	- 감사 로그: 누가 무엇을 조회·생성했는지, 어떤 출처를 썼는지 기록.
	- 버전 롤백: 보일러플레이트/템플릿/팩트의 과거 버전 복원.

13. 실제 저장 예시 (간단 JSON)

    ```json
    // Fact/KPI
    {
    "fact_id": "kpi_dau_2025q2",
    "statement": "분기 DAU",
    "value": 420000,
    "unit": "users",
    "timeframe": "2025Q2",
    "source": "IR_2025Q2_pg5",
    "approval_state": "approved"
    }

    // Quote
    {
    "quote_id": "q_2024_launchA_ceo01",
    "speaker": {"name": "홍길동", "title": "대표이사"},
    "quote_text": "신제품 A는 고객의 생산성을 높입니다.",
    "context": ["launch", "productA"],
    "allow_rewrite": false,
    "source": "PR_2024_03_launchA_v2"
    }

    // Chunk (섹션 단위 임베딩)
    {
    "chunk_id": "doc123_sec_lead",
    "doc_id": "doc123",
    "section": "lead",
    "text": "㈜모비젠은 2025년 8월 14일...",
    "embedding": "<…>",
    "keywords": ["모비젠","신제품A","출시"],
    "date": "2025-08-14"
    }
    ```

14. MVP(최소 구현) 제안 (2~4주에 가능)
	1.	수집·정제: 과거 보도자료 50~200건 + 보일러플레이트 + 연락처
	2.	청킹/임베딩: 섹션 단위(lead/quote/boilerplate 구분) + BM25+벡터 혼합
	3.	팩트 DB v1: KPI·주요 주장·승인 인용 최소셋
	4.	프롬프트 템플릿 v1: 한국어 보도자료 골격 + 금칙어 체크
	5.	초안 생성 UI: 질의 → 컨텍스트 미리보기(출처 하이라이트) → 초안 JSON → 렌더
	6.	편집/피드백 루프: 편집 결과를 학습 데이터로 회수(좋은 문장 북마크)

15. 단계적 고도화 아이디어
	- 멀티리트리버: 키프레이즈/엔티티 전용 인덱스 추가, 시간가중치·다양성 보장(스팬 다양화)
	- 지식 그래프: 제품→기능→사례→KPI 연결, “제품X 관련 최근 검증 주장” 한 방 조회
	- 퍼스널라이즈: 대상 매체/기자별 톤·관심사 반영, 맞춤형 헤드라인 후보 생성
	- 자동 미디어 키트: 초안과 함께 썸네일·대표 이미지·표 캡션 자동 제안
	- 한/영 동시 생성: 번역+후편집 파이프라인, 고유명사 보호

16. 체크리스트 (바로 시작하려면)
	- 과거 보도자료/보일러플레이트/승인 인용 모으기
	- 스타일 가이드·금칙어 정의(숫자·단위·따옴표·회사명 표기)
	- 팩트 DB 컬럼 결정: value/unit/timeframe/source/approval
