## Spring Boot 애플리케이션 테스트

### Auto-configured Data JPA Tests 

`@DataJpaTest`를 사용한 자동 구성된 Data JPA 테스트

`@DataJpaTest` 어노테이션을 사용하면 JPA 애플리케이션을 테스트할 수 있습니다.
기본적으로 `@Entity` 클래스를 스캔하고 Spring Data JPA 레포지토리를 구성합니다.
클래스패스에 내장 데이터베이스가 있으면 이를 자동으로 설정합니다. 또한, `spring.jpa.show-sql` 속성을 `true`로 
설정하면 SQL 쿼리가 기본적으로 로그에 출력됩니다. 이 기능은 어노테이션의 `showSql` 속성을 사용해 비활성화할 수 있습니다.

`@DataJpaTest`를 사용할 경우 일반적인 `@Component` 및 `@ConfigurationProperties` 빈은 스캔되지 않습니다.
`@ConfigurationProperties` 빈을 포함하려면 `@EnableConfigurationProperties`를 사용하세요.

`@DataJpaTest`에 의해 활성화되는 자동 구성 설정의 목록은 부록에서 확인할 수 있습니다.

기본적으로 Data JPA 테스트는 트랜잭셔널이며 각 테스트가 끝나면 롤백됩니다. 자세한 내용은 
Spring Framework 레퍼런스 문서의 해당 섹션을 참고하세요. 테스트 또는 전체 클래스에서 트랜잭션 관리를
비활성화하고 싶다면 다음과 같이 설정할 수 있습니다:

```java
import org.springframework.boot.test.autoconfigure.orm.jpa.DataJpaTest;
import org.springframework.transaction.annotation.Propagation;
import org.springframework.transaction.annotation.Transactional;

@DataJpaTest
@Transactional(propagation = Propagation.NOT_SUPPORTED)
class MyNonTransactionalTests {
    // ...
}
```

Data JPA 테스트는 `TestEntityManager` 빈도 주입할 수 있습니다. 이는 테스트용으로 설계된 JPA `EntityManager`의 대안입니다.

`@AutoConfigureTestEntityManager`를 추가하면 `TestEntityManager`를 자동 구성할 수 있습니다.
이 경우, `@Transactional`을 클래스나 메서드에 추가해 테스트가 트랜잭션 내에서 실행되도록 해야 합니다.

`JdbcTemplate`도 사용할 수 있습니다. 아래는 `@DataJpaTest` 사용 예제입니다:

```java
import org.junit.jupiter.api.Test;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.orm.jpa.DataJpaTest;
import org.springframework.boot.test.autoconfigure.orm.jpa.TestEntityManager;

import static org.assertj.core.api.Assertions.assertThat;

@DataJpaTest
class MyRepositoryTests {

    @Autowired
    private TestEntityManager entityManager;

    @Autowired
    private UserRepository repository;

    @Test
    void testExample() {
        this.entityManager.persist(new User("sboot", "1234"));
        User user = this.repository.findByUsername("sboot");
        assertThat(user.getUsername()).isEqualTo("sboot");
        assertThat(user.getEmployeeNumber()).isEqualTo("1234");
    }

}
```

인메모리 내장 데이터베이스는 빠르고 별도의 설치가 필요 없기 때문에 테스트에 적합합니다.
그러나 실제 데이터베이스를 사용하여 테스트를 수행하고자 할 경우 `@AutoConfigureTestDatabase` 어노테이션을 사용할 수 있습니다. 아래는 그 예시입니다:

```java
import org.springframework.boot.test.autoconfigure.jdbc.AutoConfigureTestDatabase;
import org.springframework.boot.test.autoconfigure.jdbc.AutoConfigureTestDatabase.Replace;
import org.springframework.boot.test.autoconfigure.orm.jpa.DataJpaTest;

@DataJpaTest
@AutoConfigureTestDatabase(replace = Replace.NONE)
class MyRepositoryTests {
    // ...
}
```

### Test Container 

Testcontainers 라이브러리는 Docker 컨테이너 내에서 실행되는 서비스를 테스트 코드에서 관리할 수 있도록 도와주는 라이브러리입니다.
JUnit과 통합되어 테스트 실행 전에 컨테이너를 자동으로 시작할 수 있으며, MySQL, MongoDB, Cassandra 등과 같은 실제 백엔드 서비스와 통합 테스트를 작성할 때 유용합니다.

아래 섹션에서는 Testcontainers를 테스트에 통합하는 다양한 방법을 소개합니다.

#### Spring Bean을 이용한 방식

Testcontainers의 컨테이너를 Spring Boot가 Bean으로 관리할 수 있습니다. 컨테이너를 Bean으로 선언하려면 테스트 설정 클래스에 `@Bean` 메서드를 추가하세요.

```java
@TestConfiguration(proxyBeanMethods = false)
class MyTestConfiguration {

    @Bean
    MongoDBContainer mongoDbContainer() {
        return new MongoDBContainer(DockerImageName.parse("mongo:5.0"));
    }

}
```

이후 테스트 클래스에서 해당 설정을 `@Import`하여 컨테이너를 주입받아 사용할 수 있습니다.

```java
@SpringBootTest
@Import(MyTestConfiguration.class)
class MyIntegrationTests {

    @Autowired
    private MongoDBContainer mongo;

    @Test
    void myTest() {
        ...
    }

}
```

이 방식은 `@ServiceConnection` 등의 서비스 연결 어노테이션과 함께 자주 사용됩니다.

#### JUnit 확장 사용

Testcontainers는 JUnit 확장을 제공하여 컨테이너 관리를 쉽게 할 수 있습니다. 테스트 클래스에 `@Testcontainers` 어노테이션을 붙이고, 컨테이너 필드에 `@Container`를 사용하면 됩니다.

```java
@Testcontainers
@SpringBootTest
class MyIntegrationTests {

    @Container
    static Neo4jContainer<?> neo4j = new Neo4jContainer<>("neo4j:5");

    @Test
    void myTest() {
        ...
    }

}
```

위 예제는 테스트 실행 전에 Neo4j 컨테이너를 자동으로 시작하며, 컨테이너의 생명주기는
Testcontainers가 관리합니다. 대부분의 경우, 애플리케이션이 컨테이너 내 서비스에 연결되도록 설정이 추가로 필요합니다.

#### 컨테이너 설정 인터페이스 재사용

Testcontainers의 일반적인 패턴 중 하나는 컨테이너 인스턴스를 static 필드로 인터페이스에 선언하는 것입니다. 아래 예제는 MongoDB 및 Neo4j 컨테이너를 포함하는 인터페이스입니다.

```java
interface MyContainers {

    @Container
    MongoDBContainer mongoContainer = new MongoDBContainer("mongo:5.0");

    @Container
    Neo4jContainer<?> neo4jContainer = new Neo4jContainer<>("neo4j:5");

}
```

이 인터페이스를 테스트 클래스에서 구현하거나, Spring Boot 테스트에 적용하려면 `@ImportTestcontainers`를 설정 클래스에 추가합니다.

```java
@TestConfiguration(proxyBeanMethods = false)
@ImportTestcontainers(MyContainers.class)
class MyTestConfiguration {

}
```

#### 컨테이너 생명주기

- Testcontainers 어노테이션/확장을 사용할 경우: 생명주기는 Testcontainers가 전담
- Spring Bean으로 컨테이너를 선언한 경우: 생명주기는 Spring이 관리

Spring Bean으로 등록한 경우 생명주기 동작:

- 컨테이너 빈은 다른 빈보다 먼저 생성 및 시작됨
- 모든 다른 빈이 소멸된 후 컨테이너가 중지됨

이렇게 하면 컨테이너의 기능에 의존하는 빈이 정상적으로 동작하고, 종료 시점에도 예외 없이 처리됩니다.

반면 Testcontainers가 직접 컨테이너를 관리할 경우, 컨테이너가 먼저 종료되어 클라이언트 빈에서 예외가 발생할 수 있습니다. 따라서 컨테이너 기능에 의존하는 애플리케이션 빈이 있다면 Spring Bean으로 설정하는 것을 권장합니다.

#### Service Connection

Service Connection은 원격 서비스에 대한 연결을 의미합니다. Spring Boot의 자동 구성은 서비스 연결 정보를 기반으로 원격 서비스에 연결할 수 있습니다. 이 연결 정보는 구성 프로퍼티보다 우선 적용됩니다.

Testcontainers와 함께 사용할 경우, `@ServiceConnection` 어노테이션을 통해 자동으로 연결 정보를 생성할 수 있습니다.

```java
@Testcontainers
@SpringBootTest
class MyIntegrationTests {

    @Container
    @ServiceConnection
    static Neo4jContainer<?> neo4j = new Neo4jContainer<>("neo4j:5");

    @Test
    void myTest() {
        ...
    }

}
```

위 설정은 `Neo4jConnectionDetails` 빈을 자동으로 정의하며, 이를 기반으로 Neo4j 관련 Bean들이
컨테이너 내부에서 실행되는 Neo4j와 통신할 수 있게 됩니다. 이 연결 정보는 기존 설정보다 우선시됩니다.

이 기능을 사용하려면 `spring-boot-testcontainers` 모듈을 테스트 의존성으로 추가해야 합니다.

서비스 연결 어노테이션은 `spring.factories`에 등록된 `ContainerConnectionDetailsFactory` 클래스에 의해 처리됩니다.
이 클래스는 특정 컨테이너 타입이나 Docker 이미지 이름에 기반해 `ConnectionDetails` 빈을 생성합니다.
