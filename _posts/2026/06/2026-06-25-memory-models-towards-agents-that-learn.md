![Memory Models Overview](/assets/images/2026/memory-models-towards-agents-that-learn/00-memory-models-overview.svg)

## 핵심 주장

Letta의 글은 앞으로의 AI 에이전트가 단순히 긴 컨텍스트를 쓰는 수준을 넘어, 경험에서 배우고
그 배움을 다음 작업으로 넘겨야 한다고 주장한다. 이를 위해 필요한 핵심 구성 요소가
**메모리 모델(memory model)**이다.

여기서 말하는 메모리는 데이터베이스에 대화를 저장하는 기능만을 뜻하지 않는다. 에이전트가 여러
작업을 수행하며 얻은 경험, 피드백, 시행착오를 다시 사용할 수 있는 **토큰 공간의 지식 표현**으로
압축하고 관리하는 능력을 말한다.

글의 주장은 다음처럼 정리할 수 있다.

- 장기적으로 유용한 에이전트는 특정 모델 하나에 묶이면 안 된다.
- 모델은 빠르게 교체되지만, 사용자·조직별 경험은 시간이 갈수록 가치가 커진다.
- 따라서 에이전트의 지식은 모델 가중치 안에만 있으면 안 되고, 여러 모델이 읽을 수 있는
  토큰 공간의 메모리로 보존되어야 한다.
- 이 메모리를 잘 만들고 고치는 전용 모델이 필요하며, Letta는 이를 메모리 모델이라고 부른다.

## 왜 에이전트에는 메모리 문제가 생기는가

현재의 에이전트는 작업 단위로는 꽤 잘 동작한다. 문서를 읽고, 코드를 수정하고, 도구를 호출하고,
사용자의 지시를 따른다. 하지만 여러 세션에 걸쳐 경험을 축적하고 그 결과로 행동이 안정적으로
좋아지는지는 별개의 문제다.

원문은 특히 세 가지 영역에서 이 한계를 짚는다.

1. **조직 내부 데이터와 워크플로우 적응**

   에이전트가 사내 문서와 업무 절차에 접근할 수 있어도, 그것을 장기적인 업무 감각으로 바꾸는
   능력은 제한적이다. 단순 검색이나 긴 컨텍스트만으로는 반복 업무의 암묵지까지 충분히 흡수하기
   어렵다.

2. **사람의 전문성과 가치관 학습**

   프롬프트나 persona 설정으로 행동 스타일을 어느 정도 주입할 수는 있다. 하지만 자연어 피드백,
   실제 상호작용, 작업 결과를 통해 사람처럼 계속 적응하는 수준에는 아직 못 미친다.

3. **깊은 개인화**

   사용자가 선호도나 피드백을 명시해도, 에이전트가 그것을 필요한 순간에 일관되게 떠올리고 새
   메모리로 갱신하는 것은 쉽지 않다. 상호작용 데이터는 많지만, 그 데이터를 지속 학습으로 바꾸는
   메커니즘이 약한 것이다.

## 지속 학습은 어디에 저장되어야 하는가

원문에서 중요한 관점은 **학습 결과가 모델 가중치에만 들어갈 필요는 없다**는 것이다. 오히려
에이전트의 장기 경험은 토큰 공간에 저장되는 편이 실용적일 수 있다.

그 이유는 에이전트가 앞으로 다중 모델 시스템이 될 가능성이 높기 때문이다. 코딩 모델, 컴퓨터
사용 모델, 실시간 상호작용 모델, 도메인별 모델이 함께 움직이면, 특정 모델 하나의 내부 가중치에
지식이 갇혀 있는 구조는 불리하다. 반대로 토큰으로 표현된 메모리는 여러 모델이 공통 입력으로
사용할 수 있다.

![Compound Agent System](/assets/images/2026/memory-models-towards-agents-that-learn/01-compound-agent-system.svg)

이 관점에서는 최신 모델 자체보다 **시간이 누적된 메모리**가 더 중요한 자산이 된다. 모델은 새
버전으로 교체할 수 있지만, 특정 사용자나 조직에 맞춰 쌓인 경험은 쉽게 복구할 수 없기 때문이다.

## 모델 수명과 에이전트 수명의 충돌

원문은 프런티어 모델의 출시 주기가 짧아지는 반면, 에이전트가 처리할 수 있는 작업의 시간 범위는
길어지고 있다고 본다. 모델은 더 자주 바뀌고, 에이전트는 더 긴 작업을 맡게 된다.

이 흐름이 계속되면 한 에이전트가 수행하는 작업 기간이 특정 모델의 최신성보다 길어지는 순간이
온다. 즉, 작업을 시작할 때의 최선 모델이 작업 중간에는 더 이상 최선이 아닐 수 있다.

![Model Release Gap and Agent Task Horizon](/assets/images/2026/memory-models-towards-agents-that-learn/02-model-vs-agent-lifespan.svg)

그래서 에이전트의 학습 결과는 모델 교체와 함께 사라지면 안 된다. 메모리는 모델 세대가 바뀌어도
이전되어야 하며, 새 모델은 더 강한 in-context learning 능력으로 기존 메모리를 더 잘 활용해야
한다.

## 토큰 공간 학습의 장점

토큰 공간 학습은 모델 가중치를 직접 업데이트하지 않고도, 컨텍스트를 통해 모델의 행동을 바꾸는
방식이다. 현대 LLM은 in-context learning 능력이 강하기 때문에, 잘 구성된 예시·규칙·메모리만으로도
상당한 적응이 가능하다.

이 접근의 장점은 다음과 같다.

- 폐쇄형 API 모델에도 적용할 수 있다.
- 모델을 교체해도 메모리를 옮길 수 있다.
- 새 모델의 in-context learning 능력이 좋아질수록 기존 메모리의 활용 가치도 커질 수 있다.
- 사용자별, 조직별, 프로젝트별 지식을 비교적 빠르게 반영할 수 있다.

하지만 현재의 일반 목적 LLM은 좋은 메모리를 꾸준히 만드는 데 최적화되어 있지 않다. 여러 번
요약하고 갱신하면 메모리가 점점 일반론으로 흐르거나, 반대로 너무 특정 사례에만 묶이는 문제가
생긴다. 또 같은 메모리가 세션과 모델을 넘어 안정적으로 행동 변화를 만들지도 보장하기 어렵다.

## 메모리 모델이란 무엇인가

메모리 모델은 에이전트의 경험을 장기적으로 쓸 수 있는 컨텍스트로 바꾸는 전용 모델이다. 일반
모델이 현재 작업을 잘 끝내는 데 집중한다면, 메모리 모델은 미래 작업에서 도움이 될 표현을 만들고
관리하는 데 집중한다.

여기에는 단순 요약 이상의 일이 포함된다.

- 어떤 경험이 장기적으로 중요한지 판별한다.
- 반복 업무에서 일반화 가능한 규칙을 추출한다.
- 오래된 메모리와 새 메모리의 충돌을 정리한다.
- 다른 모델에서도 통하는 표현으로 메모리를 구성한다.
- 필요하면 에이전트 하네스의 도구, 훅, 권한, 실행 흐름 같은 설정까지 조정한다.

원문은 이 문제를 **학습하는 방법을 학습하는 문제**로 본다. 단일 작업 보상을 극대화하는 것이
아니라, 여러 작업을 거치며 더 나은 메모리를 만들도록 학습시켜야 한다는 뜻이다.

## 표준 RL과 memory-native RL

표준 강화학습에서는 보통 현재 작업의 결과 보상이 중심이다. 주어진 태스크에서 더 좋은 행동을
하도록 모델을 직접 최적화한다.

반면 memory-native RL은 에이전트가 미래 작업에서 더 잘 작동하도록 만드는 **메모리 생성 과정**을
최적화한다. 안쪽 루프에서는 에이전트가 메모리를 사용해 여러 작업을 수행하고, 바깥쪽 루프에서는
그 메모리가 실제로 미래 성능을 높였는지를 기준으로 메모리 모델을 학습시킨다.

![Standard RL and Memory-native RL](/assets/images/2026/memory-models-towards-agents-that-learn/03-memory-native-rl.svg)

이 차이는 중요하다. 현재 작업을 잘 끝내는 전략과, 다음 작업을 더 잘하기 위해 배울 것을 남기는
전략은 항상 같지 않다. 예를 들어 코딩 에이전트가 버그 하나를 고치는 것과, 코드베이스에서 어떤
영역이 취약하고 어떤 테스트가 필요한지 장기 지식으로 남기는 것은 다른 목표다.

## 하네스와 가중치로의 증류

원문은 메모리가 텍스트 파일이나 컨텍스트 저장소에만 머물 필요는 없다고 본다. 에이전트 하네스
자체도 학습 대상이 될 수 있다. 도구 목록, pre/post-tool hook, 권한, 실행 흐름 같은 부분이
경험을 통해 조정된다면, 하네스도 일종의 메모리 역할을 한다.

또 모델 가중치에 접근할 수 있는 경우에는 토큰 공간 메모리를 다시 가중치로 증류할 수도 있다.
이 방식은 개인화나 효율성 측면에서 추가 이득을 줄 수 있다. 다만 폐쇄형 모델 API가 일반적인
현실에서는 토큰 공간 메모리가 더 넓게 적용 가능한 출발점이다.

## 컨텍스트에 쓰는 계산량을 확장한다

Letta는 이전 연구의 연장선에서, 질의가 들어오기 전에 모델이 컨텍스트를 미리 검토하고 정리하는
방향을 강조한다. 이를 sleep-time compute 또는 agent dreaming처럼 설명한다.

핵심은 작업 요청을 받은 순간에만 생각하는 것이 아니라, 유휴 시간에도 에이전트가 과거 경험을
정리하고 다음 작업을 위한 메모리를 개선하게 만드는 것이다. 메모리 모델이 강해질수록 이 오프라인
학습 루프의 가치도 커진다.

## 정리

이 글의 메시지는 긴 컨텍스트가 곧 장기 학습은 아니라는 점이다. 에이전트가 진짜로 배운다고
말하려면, 경험을 다음 작업에 쓸 수 있는 형태로 남기고, 그 메모리가 모델 세대와 세션을 넘어
전달되어야 한다.

앞으로 중요한 경쟁력은 특정 모델을 호출하는 능력뿐 아니라, 모델 바깥에 쌓이는 메모리를 얼마나
잘 만들고 유지하고 이전하느냐가 될 수 있다. 메모리 모델은 그 문제를 정면으로 다루려는 제안이다.

## 용어 메모

- **토큰 공간(token space)**: 모델이 입력으로 받을 수 있는 텍스트·토큰 형태의 표현 공간.
- **in-context learning**: 모델 가중치를 업데이트하지 않고, 입력 컨텍스트만으로 행동을 조정하는 능력.
- **메모리 모델(memory model)**: 경험을 장기적으로 유용한 메모리로 만들고 관리하는 전용 모델.
- **memory-native RL**: 현재 작업 보상뿐 아니라 미래 작업에 도움이 되는 메모리 형성을 학습 목표로 삼는 강화학습 방식.
- **sleep-time compute**: 사용자의 즉시 요청이 없는 시간에 컨텍스트를 정리하고 학습하는 오프라인 계산.
