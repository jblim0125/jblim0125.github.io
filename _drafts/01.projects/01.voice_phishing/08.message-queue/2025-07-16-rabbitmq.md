# 참고: RabbitMQ란?

RabbitMQ는 오픈 소스 메시지 브로커로, 다양한 시스템 간에 메시지를 안전하게 전달하는 역할을 합니다.
AMQP(Advanced Message Queuing Protocol)를 기반으로 하며, 분산 시스템에서 비동기 메시지 처리,
작업 큐, 이벤트 브로커 등 다양한 용도로 사용됩니다.

## 주요 개념

### 1. VHost(Virtual Host)

- RabbitMQ에서 논리적으로 격리된 메시지 공간입니다.
- 각 vhost는 독립적인 사용자, 권한, 큐, 익스체인지 등을 가질 수 있습니다.
- 여러 애플리케이션이 하나의 RabbitMQ 인스턴스를 공유할 때 유용합니다.

### 2. Exchange

- 메시지를 받아서 라우팅 규칙에 따라 큐로 전달하는 역할을 합니다.
- 종류: `direct`, `topic`, `fanout`, `headers` 등이 있습니다.
- 프로듀서가 메시지를 보낼 때 반드시 익스체인지를 지정해야 합니다.

### 3. Queue

- 실제로 메시지가 저장되는 버퍼입니다.
- 컨슈머가 큐에서 메시지를 가져가 처리합니다.
- 하나의 큐에 여러 컨슈머가 연결될 수 있습니다.

### 4. Binding

- Exchange와 Queue를 연결하는 규칙입니다.
- Routing Key나 Header 기반으로 메시지가 라우팅될지 여부를 결정합니다.

### 5. Routing Key

- 메시지를 전송할 때 붙이는 태그/주소입니다.
- Exchange가 Queue로 전달할지 판단하는 기준이 됩니다.

## 메시지 흐름 구조

```text
[Producer] ──► [Exchange] ──(Routing Key, Binding)──► [Queue] ──► [Consumer]
```

## Exchange의 종류와 라우팅 방식

### 1. Direct Exchange

- **특징:** 라우팅 키(routing key)가 정확히 일치하는 큐에만 메시지를 전달
- **사용 예:** 특정 작업 유형별로 큐를 분리할 때
- **예시:**

  ```text
  exchange name: upload_exchange (direct)
  routing key: file.image
  
  bindings:
    "file.image" → image_queue
    "file.text" → text_queue
  
  → file.image로 전송된 메시지는 image_queue로만 들어감
  ```

### 2. Fanout Exchange

- **특징:** 라우팅 키와 상관없이 연결된 모든 큐에 메시지를 브로드캐스트
- **사용 예:** 실시간 알림, 전체 브로드캐스트 등
- **예시:**

  ```text
  exchange name: broadcast_exchange (fanout)
  
  bindings:
    broadcast_exchange → queue1
    broadcast_exchange → queue2
  
  → 모든 큐로 메시지 전달, routing key는 무시됨
  ```

### 3. Topic Exchange

- **특징:** 라우팅 키의 패턴(와일드카드 포함)에 따라 큐에 메시지 전달
- **사용 예:** 다양한 주제별 메시지 분배(예: 로그 레벨별 분리)
- **와일드카드:**
  - `*`: 한 단어 매칭
  - `#`: 0개 이상의 단어 매칭
- **예시:**

  ```text
  exchange: topic_exchange (topic)
  routing key: user.signup.kakao
  
  bindings:
    "user.*.kakao" → kakao_queue
    "user.#" → all_user_events_queue
  ```

### 4. Headers Exchange

- **특징:** 라우팅 키 대신 메시지 헤더의 값에 따라 큐에 메시지 전달
- **사용 예:** 복잡한 조건 분기, 헤더 기반 라우팅

## Queue의 속성

Queue는 메시지를 저장하고, 순서대로 처리하는 FIFO(First-In First-Out) 구조입니다.

### 주요 속성

- **Durable:** 서버 재시작 후에도 큐가 유지됨
- **Exclusive:** 연결된 연결이 끊어지면 큐도 삭제됨
- **Auto-delete:** 소비자가 없어지면 자동 삭제

### 특징

- 메시지는 하나 이상의 Consumer가 구독 가능
- 메시지는 단 한 번 소비됨 (acknowledgment 필요)

## Docker Compose로 RabbitMQ 실행하기

```yaml
version: '3'
services:
    rabbitmq:
        image: rabbitmq:3-management
        container_name: rabbitmq
        ports:
            - "5672:5672"      # AMQP
            - "15672:15672"    # Management UI
        volumes:
            - ./rabbitmq_data:/var/lib/rabbitmq
            - ./rabbitmq_definitions.json:/etc/rabbitmq/definitions.json
        environment:
            RABBITMQ_DEFAULT_USER: user
            RABBITMQ_DEFAULT_PASS: password
            RABBITMQ_DEFAULT_VHOST: myvhost
            RABBITMQ_SERVER_ADDITIONAL_ERL_ARGS: "-rabbitmq_management load_definitions \"/etc/rabbitmq/definitions.json\""
```

- `rabbitmq_data`: 데이터 영속화용 로컬 디렉토리
- `rabbitmq_definitions.json`: 미리 정의한 vhost, exchange, queue 설정 파일

## 미리 정의한 vhost, exchange, queue 설정 방법

### 1. definitions.json 파일 생성 예시

```json
{
    "vhosts": [
        {"name": "myvhost"}
    ],
    "users": [
        {
            "name": "user",
            "password_hash": "password_hash_here",
            "hashing_algorithm": "rabbit_password_hashing_sha256",
            "tags": "administrator"
        }
    ],
    "permissions": [
        {
            "user": "user",
            "vhost": "myvhost",
            "configure": ".*",
            "write": ".*",
            "read": ".*"
        }
    ],
    "exchanges": [
        {
            "name": "myexchange",
            "vhost": "myvhost",
            "type": "direct",
            "durable": true
        }
    ],
    "queues": [
        {
            "name": "myqueue",
            "vhost": "myvhost",
            "durable": true
        }
    ],
    "bindings": [
        {
            "source": "myexchange",
            "vhost": "myvhost",
            "destination": "myqueue",
            "destination_type": "queue",
            "routing_key": "mykey"
        }
    ]
}
```

### 2. 설정 적용

`docker-compose.yml`에서 위 파일을 마운트하고, 환경변수로 `load_definitions` 옵션을 지정하면 
컨테이너 실행 시 자동으로 설정됩니다.

## 예제 구성

```json
{
  "exchange": "upload_exchange",
  "type": "direct",
  "bindings": [
    {
      "routing_key": "file.image",
      "queue": "image_queue"
    },
    {
      "routing_key": "file.json",
      "queue": "json_queue"
    }
  ]
}
```

**메시지 전송 예시:**

```text
routing_key = "file.image"
body = '{"filename": "cat.jpg"}'

→ 이 메시지는 image_queue로만 들어가고, json_queue에는 안 들어감
```

## 요약

| 구성요소    | 설명                                                 |
| ----------- | ---------------------------------------------------- |
| Exchange    | 메시지를 받고 어떤 큐로 전달할지 결정하는 라우터     |
| Queue       | 실제 메시지를 보관하고 소비자가 가져가는 저장소      |
| Binding     | Exchange와 Queue 사이의 연결 규칙 (Routing Key 기준) |
| Routing Key | 메시지가 어디로 갈지 판단하는 주소표                 |
