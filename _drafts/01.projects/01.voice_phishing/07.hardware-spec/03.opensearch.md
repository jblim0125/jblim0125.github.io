# Open Search

## 개요

본 문서는 하드웨어 스펙 산정을 위한 검색엔진(OpenSearch)의 성능에 따른 하드웨어 요구조건을 조사한 내용입니다.

## 참고 자료

`https://opensearch.org/blog/opensearch-performance-2-14/`

## 요구조건

데이터 : 월 440만건, 5년치 데이터 : 2억6천4백만건
초당 처리량 : 100건의 데이터(검색) 처리

## 하드웨어 구성

```text
master - data node
       - data node
```

1. 데이터 노드 구성
    - 노드 수: 2개
    - CPU: 각 노드당 4 vCPU
    - 메모리: 각 노드당 8GB RAM
    - 디스크: 고속 SSD, 각 노드당 최소 500GB

2. 클러스터 설정 최적화
    - 샤드 구성: 인덱스당 샤드 수를 최소화하여 오버헤드를 줄입니다.
    - 복제 설정: 필요에 따라 복제본 수를 조정하여 가용성과 성능을 균형 있게 유지합니다.
    - 메모리 설정: JVM 힙 메모리를 전체 메모리의 50% 이하로 설정하여 GC 오버헤드를 최소화합니다.
    - 인덱스 설정: index.codec을 zstd로 설정하면, 쓰기 처리량이 최대 14% 향상되고 저장 공간도 절약됩니다.
