# Nginx

## 개요

본 문서는 하드웨어 스펙 산정을 위한 nginx 의 하드웨어 구성 별 성능 정보를 제공한다.

## 참고 자료

![2core](https://www.rootusers.com/wp-content/uploads/2016/03/web-server-performance-benchmark-1-cpu-core-1.jpg)

1core - 초당 3만건
2core - 초당 5만건

Nic IRQ + CPU Affinity 가 설정된 상태에서 일반적으로 1 Core 는 1~2Gbps 의 암호화되지 않은(http) 데이터를 처리할 수 있다.
하나의 연결은 1MB 정도의 메모리를 사용한다.

## 정보

1. 전제 조건
    Nginx : Reverse Proxy +
    WAF : ModSecurity 를 이용한 웹방화벽

2. 레퍼런스 기반 사양 가이드

    A. CPU (Core 수)

    | 처리량   | 일반 요청   | TLS(ModSecurity) 요청 포함 |
    | -------- | ----------- | -------------------------- |
    | 2~4 Gbps | 4 cores     | 6 cores                    |
    | 5~8 Gbps | 8 cores     | 12 cores                   |
    | 10 Gbps  | 12~16 cores | 16~24 cores                |

    B. Memory (RAM)

    Nginx는 메모리 집약형은 아니지만, 다음을 고려해야 합니다:
        - Worker 프로세스의 버퍼 사용량
        - 커넥션 테이블
        - File descriptor, large buffer tuning
        - OS-level 파일 캐시 활용

    | 트래픽 기준 | 일반                   | TLS(ModSecurity) 요청 포함 |
    | ----------- | ---------------------- | -------------------------- |
    | ~2Gbps      | 1~GB                   | 2~GB                       |
    | ~4Gbps      | 4~GB                   | 8~GB                       |
    | 10Gbps      | 8~16GB (최소 8GB 권장) |                            |

    추천:
        - 커널 tunables (tcp_max_syn_backlog, net.core.somaxconn, worker_connections 등) 조정 시 여유 RAM이 필요

3. 네트워크 및 병목 관련 주의점
    - IRQ Pinning / CPU Affinity: NIC interrupt를 특정 코어에 분산
    - sendfile, tcp_nopush 등의 최적화 설정 필요
    - Nginx worker 수 = CPU 코어 수에 맞춰 조정 (worker_processes auto)

## 1Gbps 이상 처리 시

    | 항목   | 권장 사양                                                 |
    | ------ | --------------------------------------------------------- |
    | CPU    | 4코어 이상 (최소 3.0GHz 클럭)                             |
    | Memory | 8GB 이상                                                  |
    | 디스크 | SSD 이상 (NVMe 권장)                                      |
    | 설정   | IRQ Pinning, CPU Affinity, Nginx + sysctl 네트워크 최적화 |
