## 참고자료

### 1. Spring Cloud Gateway의 구조적 한계

- Netty는 단일 스레드 I/O 모델 → 단일 연결 처리 시 CPU 코어 활용에 한계 있음
- Spring Gateway 자체는 HTTP Streaming / File Upload 처리에 최적화되어 있지 않음
- 대용량 트래픽에서 GC, TLS, chunking 등이 병목 요인 가능

### 2. 성능에 영향 주는 요소들

1. Keycloak 인증 처리 방식:
    - Keycloak 서버와 직접 REST 요청 → 성능 저하 요인.
    - JWT 토큰 파싱 방식 → 성능 영향 적음 (권장).
2. 사용된 필터의 무게:
    - 단순 로깅, 헤더 추가 필터는 TPS에 큰 영향 없음.
    - 로깅 + Auth 관련 커스텀 필터 2개는 약 10~15% 오버헤드.
3. Backend API 속도:
    - Spring Cloud Gateway는 비동기지만, 백엔드 API 응답이 느리면 전체 TPS가 제한됨.
4. GC 튜닝 및 Netty 설정:
    - GC가 자주 발생하지 않도록 메모리 마진 확보 필요.
    - Netty connection pool 및 thread 설정 조정 시 TPS 향상 가능.

### 3. JWT 기반 토큰 검증

Keycloak 인증을 JWT 기반으로 설정 시 토큰 검증이 Gateway 내에서 이루어져 효율적입니다.

### 4. 네트워크 및 시스템 설정

| 항목              | 설정                                                                           |
| ----------------- | ------------------------------------------------------------------------------ |
| OS 커널           | tcp_rmem, tcp_wmem, net.core.rmem_max, somaxconn 최적화                        |
| 파일 업/다운 제한 | spring.codec.max-in-memory-size, max-request-size, uploadStrategy 등 조정 필요 |
