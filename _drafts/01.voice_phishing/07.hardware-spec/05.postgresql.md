# Postgresql

## 개요

본 문서는 하드웨어 스펙 산정을 위한 Postgresql 의 성능에 따른 하드웨어 요구조건을 조사한 내용입니다.

## 정보

PostgreSQL의 초당 처리 성능(CPS: Commands per Second)은 CPU 및 메모리 성능, 쿼리 종류(READ vs WRITE),
클러스터 구성 방식에 따라 달라지므로 정확한 수치는 환경에 따라 상이합니다.

1. 시스템 구성 전제
    - 처리량 요구: 초당 1000건 (TPS = 1000, 800 read + 200 write)
    - PostgreSQL 노드 수: 3개 (Replication 기반 클러스터 구성)
    - 읽기/쓰기 분리: 1개의 Master 노드가 write 처리, 나머지 2개의 Replica 노드가 read 처리
    - 애플리케이션 레벨에서 읽기/쓰기 분산 처리 가정

2. PostgreSQL 일반적인 처리 성능

    PostgreSQL은 일반적인 서버급 성능에서 다음과 같은 처리량을 가집니다:

    | 하드웨어 스펙 | 예상 TPS (SELECT 기준) | 예상 TPS (INSERT/UPDATE 기준) |
    | ------------- | ---------------------- | ----------------------------- |
    | 4vCPU / 8GB   | 2,000~4,000            | 500~800                       |
    | 8vCPU / 16GB  | 6,000~10,000           | 1,500~3,000                   |

    단일 노드에서의 성능이며, 쿼리 복잡도, 인덱스, 동시성 설정 등에 따라 달라질 수 있습니다.

## 자원 계산

1. Write 처리 노드 (1대 - Master)
    - 처리량: 초당 200 write
    - 요구사항:
    - TPS 200 이상의 write 처리 능력
    - 예상 최소 사양:
    - vCPU: 2~4 core
    - Memory: 4~8 GB

    write가 상대적으로 적기 때문에 고사양이 필요하진 않음. 다만 동시성 제어 및 replication 오버헤드 고려 시 4vCPU/8GB 이상이 적절.

2. Read 처리 노드 (2대 - Replica)
    - 처리량: 초당 800 read → 각 노드당 400 read 처리
    - 요구사항 (노드당):
    - SELECT TPS 400 이상 필요
    - 예상 최소 사양 (노드당):
    - vCPU: 2 core
    - Memory: 4 GB

    대부분의 read query가 단순한 SELECT라면 이 수준으로도 충분합니다. 복잡한 join, 인덱스 부족 등 성능을 저해하는 요인이 있으면 상향 조정 필요.

3. 최종 요약: 노드당 자원 요구

    | 노드 유형 | 역할       | 초당 처리량 | 필요 vCPU | 필요 Memory |
    | --------- | ---------- | ----------- | --------- | ----------- |
    | Master    | Write 전담 | 200 TPS     | 4 core    | 8 GB        |
    | Replica 1 | Read 전담  | 400 TPS     | 2 core    | 4 GB        |
    | Replica 2 | Read 전담  | 400 TPS     | 2 core    | 4 GB        |

    전체 클러스터로 보면 약 8 core / 16 GB RAM 수준의 클러스터 자원이 필요.
